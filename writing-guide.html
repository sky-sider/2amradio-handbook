人物 / シナリオ執筆

シナリオライターのための執筆・設定管理ガイド

まず「どんな展開があるか」を知りたいとき

特別放送の企画や応募原稿を書く場合は、特別放送 企画・お便り制作ガイドに募集の仕組み・応募と紹介の違い・テーマ別の作例をまとめました。

コードや数値からではなく、物語のシチュエーション図鑑から「しばらく不在→復帰」「他人の声を聴いてから返歌」「街でのすれ違い」などの展開を選んでください。作例は新規執筆のためのサンプルであり、現行の原稿と区別しています。

基準：ゲーム v4.9.22。人物ごとの追加解釈は採用前の編集案。人物バイブルは既存の実装と物語を変更せずにライターを支援するためのものです。

「確定」と「未確定」を混ぜない#

区分 具体例 執筆時の取り扱い
実装で確認済み 古時計は元時計修理業、午前3時の配達員は夜間配送に従事 原則尊重。新たな変更はコードと記録を照合
実装上の可変事実 夜明けの猫が仕事を離れたか、配達員と妹との関係がどうなったか 保存された選択や flags を判定したときだけ断定
既存作品からの解釈 古時計が人の予定を嬉しく感じる、金魚が感情を言葉にするのに時間がかかる 人物の方向性として参考にするが、本人の確定告白にしない
新しい由来・内面の仮説 なぜそのラジオネームを付けたか、幼少期の具体的な出来事 未確定。採用決定までは公式設定として公開・参照しない

原則：人を詳しくするために過去を確定させすぎない。書かなかった部分が、プレイヤーとリスナーの間の余白にもなる。

新しいお便りを作る7段階#

  1. 差出人：人物ページで主題と「同じ人が使いそうな声」を確認する。
  2. 着地点：大きな転機、何気ない一日、笑える出来事、語らない余白のどれを描くか決める。
  3. 事実の階層：書きたい出来事が実装確定／条件付き／新規提案のどれかに分類する。
  4. 行動の根拠：人物の SIM_PROFILES の日常行動候補、時刻、生活関係を参照。何も起きない日も認める。
  5. 件名＋本文：まず具体物1点を選ぶ。本人の事情を長く説明しすぎず、手紙を1通として読める長さでまとめる。
  6. DJの返答：本文に書かれた範囲だけに答える。3方向を用意し、選択ごとに無理な事実を加えない。
  7. 分岐とテスト：直前の手紙が未紹介、特別放送で後送り、最終放送を選ばず第500夜まで進行、の各ケースで矛盾しないか試す。

お便りの構成テンプレート#

差出人: 既存の listener ID
件名: 具体物・行動・小さな疑問から
本文: 挨拶（任意）→ 今日の出来事 → 一瞬の感情/観察 → 余韻
返答A: 受け止める（勝手に励ましきらない）
返答B: 具体的に尋ねる（既存事実の範囲）
返答C: 軽いユーモア／余白を残す（人物に合う場合のみ）
既読依存: 無/有（有ならキーと分岐を記述）
セーブ影響: 関係する flags / trust / reflection / agency / stress など
時系列: 届く夜と、遅延・持ち越し時の成立範囲
採用状態: 草稿 → 監修 → 実装 → 全モードQA → 確定

声を書き分ける#

  • 夜明けの猫：迷いを押し切らない。「うれしい。でも…」という両立。
  • 古時計：道具と記憶。落ち着いていて説教にならない。
  • 眠れないパン屋：仕事の細部と自分へのツッコミ。温かい笑い。
  • 月の裏側：架空のルールを大真面目に構築し、台所へ戻る。
  • 午前3時の配達員：業務報告の冗談。その奥に短い本音。
  • 透明な金魚：感情に名前を付けるまでのためらい。
  • 砂糖を三杯：味、空、短い会話。押しつけない観察。
  • 名前はまだありません：説明しない勇気。短い文章と空白。
  • 終点のひとつ前：時刻、場所、一行の気持ち。余韻。
  • 逆さまの傘：花屋の具体性と、花ではない趣味。
  • 三角定規：図面や予定の余白。素直な質問と好奇心。
  • 冷蔵庫の明かり：工程、器、休息。大仰な感情表現を避ける。

長期プレイと世界観の絶対ルール#

  • 未紹介のお便りはDJの既知情報にしない。 リスナー本人が経験した出来事と番組が知った出来事を分離。
  • 近況を過去の大事件の続きに固定しない。 後年の手紙は、以前の手紙を読んでいない場合にも成立する。
  • 誰も100夜で人生を終えない。 任意閉局は番組の終わりであり、12人の生活は続く。
  • 全員を同じ成長曲線にしない。 変わらない楽しみ、仕事の失敗、冗談の夜があってよい。
  • 返答で「無理に解決」しない。 DJは人生を管理せず、今夜届いた声を聴く。
  • 長期で繰り返す本文は具体物を入れ替えただけにしない。 話題の焦点と関係の角度を変える。
  • ラジオネームの由来を採用する場合は、既存の全登場箇所と衝突しないか監修する。 今回の案を現時点で公式の過去とみなさない。

監修時にチェックする質問#

  • [ ] その名前を別のリスナーに入れ替えても成立する文になっていないか。
  • [ ] 本文にない性格や過去を、DJが勝手に説明していないか。
  • [ ] 前回未紹介・長期不在・モード別の履歴を考慮しているか。
  • [ ] 既存の人生分岐や関係に勝手に決着をつけていないか。
  • [ ] セーブ差分・実際に読んだ手紙のみで回想しているか。
  • [ ] その人物らしい日常の面白さが残っているか。
