# 開発参加・環境構築

> **資料基準:** ゲーム v4.9.22 ／ **資料状態:** 実装コードを基準にした開発者向け整理。未検証・提案は明記。

## 実行方法

本体はライブラリやビルドツールに依存しない静的サイトです。ゲーム本体の6ファイルを**同じ階層**に置き、`index.html`をブラウザで開きます。スマホで `file://` のスクリプト読込が制限される場合は GitHub Pages など HTTPS 配信を使います。

```text
radio_2am/
├─ index.html       # HTMLの入口・4つのスクリプトを読み込む
├─ style.css        # レスポンシブレイアウトと演出
├─ listeners.js     # 12人の基本設定・生活行動・シミュレーション
├─ letters.js       # 固定手紙・返答選択肢・曲・章テキスト
├─ events.js        # イベント・分岐・季節・関係・特別放送
└─ script.js        # アプリ本体・描画・保存・DJ・最終放送
```

**読み込み順は固定**：`listeners.js` → `letters.js` → `events.js` → `script.js`。グローバル定義と `s` に依存しているため、順番変更や `type="module"` の無計画な導入は避けます。

## 開発者として最初に確認する項目

- HTML・CSS・JavaScriptがブラウザで動作するか。
- `script.js` の `SAVE`／`READER_SAVE` 等のキーを変更していないか。
- 第1夜の起動、3通の選択、返答の選択、放送後の進行ができるか。
- 第78→79夜（第4章）、第92→93夜、第99→100夜、最終放送の閉局ができるか。
- 既存のバックアップを読み込めるか。**実セーブの複製で試し、元データを上書きしない。**

## 変更ワークフロー

1. まず本文・イベント・保存・描画のどれを変えるか決める。
2. 対象関数を[ソース索引](source-index.html)で検索する。
3. 関連するフラグ、既存セーブ、返答番号とタグの意味を調べる。
4. 最小の差分で変更し、旧セーブからの継続と新規開始の両方をテスト。
5. 通常モード・おたより中心・読書モードを区別して回帰試験。
6. 結果を[変更履歴](changelog.html)へ記録。本文の改稿には既読保持の考慮が必要。

## デバッグの基本

```js
// 開発者ツールのコンソールで（ゲームが読み込み済みのとき）
console.table({night:s.night, phase:s.phase, tab:s.tab, mode:s.nightBroadcastMode});
console.log('選択', s.chosen, '紹介済み', s.played.length);
console.log('生活', s.simState?.people?.cat);
```

`localStorage.clear()` は**禁止**（本編・読書データを消し得る）。リセットが必要なら必ずバックアップと別ブラウザプロファイルを使います。
