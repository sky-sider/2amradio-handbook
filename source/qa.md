# テスト計画・受け入れ条件

> **資料基準:** ゲーム v4.9.22 ／ **資料状態:** 実装コードを基準にした開発者向け整理。未検証・提案は明記。

## 標準回帰テスト

| 分類 | 入力条件 | 受け入れ条件 |
|---|---|---|
| 起動 | 第1夜・新規 | JSエラーなし。案内と手紙が見える。 |
| 初期章 | 第1〜14夜 | 分岐が選択に応じ、未紹介を既読扱いしない。 |
| 章移行 | 14→15、28→29、50→51、64→65、78→79、92→93、99→100 | 夜数と表示が自然。 |
| 予約企画 | 第4章と特別放送が重なる夜 | 企画を潰さず、章便箋は保留。 |
| モード | manual／letters／reader | 本編と読書の操作・保存境界を保持。 |
| 自動DJ | 第1〜500夜の複数初期条件 | 出番の偏り、誤推定、重複返答を監査。 |
| 長期 | 第500→501夜 | 1,500通規模の履歴でも読書・保存できる。 |
| 閉局 | 第130→132夜など | 予告、3通、証明書、再開不可。 |
| 復元 | JSON／圧縮／保存失敗 | 旧データを壊さない。 |
| 表示 | 320・390・1280px | 横はみ出しやボタンの欠落なし。 |

## 改修タイプ別に必要な比較

- **文面のみ**：新旧で紹介ID・順序・返答タグ・人物状態が一致。既読本文は保持。
- **選出ロジック**：人数分布だけでなく、第4章の特別放送・最終放送まで検証。
- **UIだけ**：s.rng・s.played・生活状態が操作前後で変わらない。
- **保存系**：通常JSON、圧縮、旧版復元、容量不足、リセット、再起動を試す。

## 性能基準（参考）

v4.9.20〜22の修正では、500夜相当のデータでしおり200通の表示が約135ms→13ms、日誌しおり操作が約45ms→9msになったというPC上の検証記録があります。**数字を保証値として扱わない**でください。端末、ブラウザ、データによって変わります。

## Android実機確認

Chrome等で第100・130・300・500夜のテストセーブを開き、スクロール、日誌、しおり、バックアップ、再起動、最終放送PNG保存を検証。実機未確認の場合は、検証済みとは書かない。
