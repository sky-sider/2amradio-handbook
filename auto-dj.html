聴くだけの夜：自動DJの詳細

資料基準: ゲーム v4.9.22 ／ 資料状態: 実装コードを基準にした開発者向け整理。未検証・提案は明記。

何をする仕組みか#

実装確認：自由文生成AIではありません。候補のお便りを数値評価し、既存／状況別に用意された返答から最も適切なものを選び、放送用の文章を整えて一夜の読書ページとして保存します。

自動で1夜を作る流れ#

readerProduceNight()
 ├─ 配達された候補を取得
 ├─ autoDJPickLetters() → 紹介する最大3通を選択
 │   ├─ 記念放送の優先枠
 │   ├─ 直近27夜・通算の登場補正
 │   ├─ 同じ人を同じ夜に重複させにくい補正
 │   ├─ 似た雰囲気の手紙を並べすぎない補正
 │   └─ autoDJOrderNightLetters() で並びの緩急を調整
 ├─ 各手紙に対して専用返答を採点
 │   ├─ 相手の具体的な話題に合うか
 │   ├─ 以前の返答と重なりすぎないか
 │   ├─ 深刻な相談に不適切な冗談でないか
 │   ├─ 未紹介の出来事を知っているように話さないか
 │   └─ 特別放送の文脈と合うか
 ├─ 演出・曲・本文を構成
 ├─ played／人物の状態を通常と同じシステムで更新
 └─ reader.pages に保存して再表示に使う

紹介する手紙のスコア：autoDJPickLetters#

採点は候補ごとの合算です。下記はv4.9.22のコードにある係数です。

要因 加点／減点
ベース +2.0
最近42夜以内に同じ人の声を紹介した +1.65
前回紹介からの間隔 min(1.45, timeGap/15)
同じ夜に同じ差出人がもういる −5
先に選ばれた手紙と雰囲気が異なる +1.1
どちらも内省的 +0.35
特別放送投稿 +1.0
長期新作 laterlife4914 +1.25
リスナー同士の交流便り +2.4
同一本文の最近10夜以内の再選出 −5.5
最近の紹介の少なさ clamp((直近27夜の平均−当該人の回数)×0.045, −1.4, 2.0)
通算の紹介の少なさ clamp((通算平均−当該人の回数)×0.007, −0.5, 0.8)
同点付近のゆらぎ ハッシュから0〜約1.65

必須注意：記念放送の先行確保があり、すべての候補が同一スコアで競うわけではありません。第50夜と長期記念回でも先行枠数が異なります。

返答の選び方#

autoDJReplyScore は手紙の heavy（重さ）、reflective（内省）、bright（明るさ）、playful（遊び心）を判定し、返答タグと文面から得点を付けます。

  • 深刻な手紙には empathy／space／caution を優遇、humor を大幅減点。
  • 明るい報告には祝意、内省には問い・振り返りを適度に優遇。
  • 本文に根拠がない感情・事実・当夜の天候・解決済み扱いを抑制。
  • 同じ返答全文の近接反復、特別放送の同段落の反復、最近使ったタグの多用を抑制。
  • 同じ人物の既知の背景との整合や、前の放送への言及も採点する。
  • 候補が不適切な場合は、より具体的で事実に沿った候補が選ばれるようにする。

自動DJの声と文章の多様性#

READER_DJ_VOICE や READER_RADIO_PHRASING_4915 に従って、口調・オープニング・つなぎ・締めを構成。v4.9.15ではオープニング29種類、締め30種類、つなぎ20種類の実績が検証されましたが、実際の候補や数値はソースが正です。

読書用データの基本#

reader:{schema:1,pages:[],viewIndex:-1,scrollY:0,dj:{tags:[],lastPlanNight:-999}} を基礎にページを追記。pages に当夜の night、letterIds、interludes、song 等を保存。再度ページを開いたときに再抽選しません。

デバッグすべきこと#

  • 「冷蔵庫の明かり」など出番の少ない人が再び1通程度になっていないか。
  • 未読の手紙の内容を自動DJが知っているように話していないか。
  • 深刻な悩みのあと唐突に冗談が続かないか。
  • 選出・返答は新旧で同じなのに表示文だけが異なる修正では、内部の演出履歴を変えていないか。
